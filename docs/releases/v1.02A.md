# EventClock v1.02A — External Reset Times and Usage Recovery

**Status:** local release candidate for publication. Automated validation is complete; physical iPhone validation is partially complete. This is not an App Store release.

## Highlights

- **Recovery timers:** enter a service name and an exact future reset time, see a live countdown, receive a notification, then edit/reschedule or cancel.
- **Multiple simultaneous recovery timers:** each has independent state and notification identity.
- **Relative-event timers:** record an event and start a countdown measured from that timestamp.
- **Unified Recovery screen:** expected reset time, remaining time, status, edit/cancel controls, and a 15-second notification test.
- **Time correctness:** absolute `Date` storage, device-local date display, rejection of past deadlines, relaunch recovery, immediate notification scheduling, and reconciliation of pending requests.
- **Estimate labeling:** user-entered reset times are clearly presented as estimates unless the service guarantees the exact time.
- **No account access:** no scraping, API keys, private usage data, or unauthorized service integrations.

## Validation

- 63 automated tests: 54 Core and 9 notification-platform tests, 0 failures.
- iOS simulator-SDK and device-SDK builds succeeded without signing.
- Physical iPhone validation confirmed exact reset deadlines, rescheduling, relative-event timers, and notification delivery.
- Outstanding physical checks: independent cancellation, multi-timer recovery, past-deadline rejection, and final data-migration checks.

## Known limitations

- Reset times are manually supplied estimates; EventClock cannot detect a service’s actual reset time.
- iOS controls notification delivery; notifications are not guaranteed.
- There is no continuous background rule engine. Rules execute when the app processes an event.
- No HealthKit, AlarmKit, watchOS, or real sensor integrations yet.
- The current rule editor exposes one flat AND/OR/NOT group; deeper nesting is supported by the engine but not fully authorable in the UI.
- No App Store distribution has been prepared.

## Installation

Requirements: Xcode 27 / Swift 6, iOS 17+, and an Apple signing team.

1. Open `App/EventClock.xcodeproj`.
2. Select the EventClock target → Signing & Capabilities → choose your team.
3. Build and run on an iPhone.
4. Allow notifications.

The app displays `EventClock v1.02A` and technical build `5`. Apple-facing numeric metadata is `1.1.0`.
